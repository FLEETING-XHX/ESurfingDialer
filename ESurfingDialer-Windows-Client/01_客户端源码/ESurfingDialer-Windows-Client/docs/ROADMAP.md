# 未来开发方向

> 本文只记录尚未完成的工作及其优先级。已完成的能力单独列出，不能据此推断其他项目已经提供。

## 已完成：增强连接策略

“增强连接”已完成并进入当前客户端，不再属于后续待办。

- 正常运行时不重复认证、不增加网络探测；认证核心固定每 5 秒更新健康状态，客户端在增强模式下每 5 秒读取一次本地状态。
- 认证核心异常退出、健康状态过期、关键线程停止、认证心跳长期未确认或持续掉认证时，监督层才介入恢复。
- 具备启动宽限、连续异常确认、30/60/120 秒退避、最大恢复次数和手动停止取消恢复，避免网络抖动导致反复认证。
- 常态健康轮询不写日志；日志仅记录异常、恢复和达到上限等有价值事件。核心原有的正常心跳与掉认证恢复始终保留。

## 1. 稳定性、资源占用与回归保障

这是后续工作的最高优先级。轻量、稳定、后台开销小优先于新增功能。

- 在真实校园网、游戏和长时间后台运行场景下采集 CPU、内存、磁盘写入、网络探测和日志增长数据，避免凭感觉调高轮询频率。
- 持续检查认证、心跳、重认证、网络探测和进程恢复的边界条件，优先修复可能造成长时间断网、循环恢复或误判的缺陷。
- 扩充关键路径的回归测试，并覆盖网络切换、休眠唤醒、断网恢复、认证页异常和手动停止等场景。
- 定期清理重复逻辑、过期配置和构建垃圾；明确客户端界面、认证核心、安装脚本和部署文档的职责边界。
- 继续坚持账户信息最小化保存、日志脱敏导出和有限日志读取，防止隐私泄露与长期运行的磁盘膨胀。

## 2. 离线部署、安装包与新手文档

- Windows 客户端和 Docker 软路由版继续优先支持离线安装，避免首次部署依赖临时公网下载。
- 完善截图化、面向新手的部署教程，覆盖安装、配置账户、启动、状态确认、日志导出和常见故障排查。
- 每次发布提供版本说明、适用平台、校验信息和清晰的升级步骤；保留旧安装包名称，不强制重命名或替换历史文件。
- Docker 版本继续降低无公网软路由环境的部署门槛，并保持配置与设备身份文件可安全保留。

## 3. 使用体验与 UI

- 根据实际反馈持续优化主页、账户管理、日志和设置的布局与文案，保持常用操作直观且页面简洁。
- 更清楚地区分连接中、已连接、掉认证、自动恢复和需要人工处理的状态，并通过托盘图标同步展示。
- 优化多账户添加、编辑、切换和删除流程，减少新用户的配置步骤。
- 完善网络状态展示、日志筛选和错误提示，帮助用户判断问题来自账号、校园网、认证页还是本地网络。

## 4. 兼容性与反馈闭环

- 收集不同学校、运营商认证页面及网络环境下的脱敏日志与复现信息，持续改善兼容性。
- 在设置页保留仓库入口；仅在评估清楚安全性、离线行为和用户控制方式后，再考虑检查更新能力。
- 对新的认证异常先形成可复现样本与回归用例，再调整恢复策略，避免针对单一学校做高风险特例。

## 5. 发布规范

跨平台版本发布后，统一采用以下文件命名：

| 平台 | 文件命名 |
| --- | --- |
| Windows 客户端 | `ESurfingDialer-Windows-vx.x-Setup.exe` |
| macOS 客户端 | `ESurfingDialer-MacOS-vx.x-Setup.exe` |
| Docker 软路由版 | `ESurfingDialer-Docker-vx.x.zip` |

## 6. macOS 适配

macOS 适配排在 Windows 与 Docker 的稳定性、离线部署和体验完善之后。

- 保留 Java 认证核心，另行研究 macOS 客户端适配方案；不能直接复制 WPF、Windows 托盘或注册表逻辑。
- 按 macOS 规范实现界面、托盘状态、开机启动、日志目录和安装方式，并提供离线安装包与新手说明。
- 正式发布前覆盖常见 macOS 版本、网络切换、休眠唤醒和后台运行场景。
