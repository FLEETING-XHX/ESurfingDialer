# 新版 UI 与连接恢复

本轮为 2.0 的正式本地安装包改动，尚未推送 GitHub。
Docker 代码仅作为参考，本轮没有修改 Docker 的运行逻辑。

## 界面和使用

- 主页：点击“校园网”卡片连接；连接中或已连接时点击可停止/断开。状态点和三格信号随认证状态变化。
- 网络状态：显示活动以太网/Wi-Fi 接口的上下行速率及趋势，不是校园网账号的剩余流量，也不是单独某个应用的流量。
- 账户管理：从底部弹出，可选择账户；右上角加号添加账户，“编辑账户”显示编辑和删除按钮。
- 顶部账户卡仅展示当前账户：有备注显示备注，没有备注显示账号；点击不再打开账户菜单。
- 下载速率与下载曲线为绿色，上传速率与上传曲线为珊瑚红。
- 切换正在使用的账户时，先停止旧核心再使用新账户连接。删除账户需要确认。
- 日志页：只显示简易事件；完整日志入口位于设置页。
- 设置修改后自动保存；主页、日志、设置的底部导航保持一致。

### 设置含义

| 设置 | 行为 |
| --- | --- |
| 开机自启 | 登录 Windows 后启动客户端 |
| 启动后最小化到任务栏后台 | 仅开启“开机自启”后显示；开机启动时隐藏窗口并保留托盘图标，手动打开仍显示窗口 |
| 自动连接 | 客户端启动后自动连接当前账户 |
| 增强连接 | 允许客户端监视并恢复异常退出/长时间无有效状态的认证核心；关闭不等于关闭核心内正常的心跳与掉认证恢复 |
| 详细日志 | 查看近期客户端与核心日志；完整留存内容可导出 |
| 导出日志 | 选择位置生成 ZIP，不导出账户配置、加密密码或账户列表 |
| GitHub | 打开合并后的 ESurfingDialer 仓库 |

旧版单账户配置会迁移为账户列表，密码继续使用当前 Windows 用户的 DPAPI 加密。
配置文件损坏时不会用空配置覆盖原文件。配置修改前会保留上一份备份。
预览版与旧版使用相同的用户数据目录，体验前请退出旧客户端，勿同时启动两份认证程序。

## Docker 修复对照

| Docker 中的经验/修复 | Windows 本轮处理 |
| --- | --- |
| 心跳间隔过长导致掉认证 | 心跳间隔上限默认 240 秒 |
| 登录接口成功不代表已稳定认证 | 登录后确认 keep 心跳，确认失败刷新网络信息并重试，不直接显示已连接 |
| 临时网络探测失败被当成掉认证 | 已认证时继续心跳，认证页探测加入连续次数、登录宽限和重试冷却判断 |
| 重认证后的失败计数残留 | 成功登录/心跳后重置对应失败计数 |
| 重试复用失效连接 | 会话重置时清理 API 连接池，拒绝异常 HTTP 响应并关闭响应资源 |
| 健康状态被旧文件或半写入文件污染 | 核心原子更新健康 JSON，客户端检查启动时间、更新时间和认证心跳新鲜度 |
| 认证线程停止但外壳仍在运行 | 增强连接开启时监测异常状态并恢复，不仅检查 Java 进程存在 |
| 外部重启干扰正在进行的恢复 | 探测防抖，核心退出后退避重启；手动停止或切换账户会取消旧的待执行重连 |

Windows 特有修复：

- 退出客户端时停止认证核心；手动停止先通知核心尝试注销，超时再结束进程。
- 核心连续异常退出时限制自动重启次数，避免无限快速重启。
- 停止核心的等待不阻塞主界面，账户切换期间避免并发操作。
- 日志滚动、近期日志限量读取和导出脱敏，减少长期运行时日志无限增长或界面卡顿。
- 保留 Windows 64 位模拟器和原生接口适配，没有直接覆盖 Docker/Linux 平台代码。

## 本机预览

本轮本地预览文件位于：

```text
dist/ESurfingDialerLite-UI-Preview/ESurfingDialerLite.exe
```

预览目录包含新版认证核心和 Java 运行时；需要已安装 .NET 10 Desktop Runtime。
本机已有对应环境，预览无需联网下载依赖；这不是可直接分发给所有电脑的完整离线安装包。
部署程序本身可以离线，实际校园网认证仍需要连接学校网络。

Visual Studio 请打开本目录的 `ESurfingDialerWindowsClient.slnx`，不要打开合并前旧目录下的同名工程。
主工程在核心构建完成后会自动把 JAR 复制到输出目录，避免重新生成后缺少 `core/client.jar`。

## 构建与回归检查

在此源码根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Build-Core.ps1 -Offline -Regression
dotnet build app/ESurfingDialerLite/ESurfingDialerLite.csproj --no-restore
dotnet run --project tests/ClientRegression/ClientRegression.csproj -- artifacts/ui --core
```

核心构建使用 JDK 17 启动 Gradle 8.4，使用 JDK 21 编译/运行项目。
脚本默认使用本机的 `D:\Java\JDK17` 和 `D:\Java\JDK21`，其他机器通过 `-Jdk17`、`-Jdk21` 指定路径。
离线构建要求事先准备好工具和依赖缓存；首次联网准备时，Gradle 分发优先使用华为镜像并校验 SHA-256，Maven 依赖优先阿里云。

本轮已通过：

- 54 项客户端回归检查：配置迁移、界面布局与导航、账户编辑、导出脱敏、健康状态、真实 Java 子进程重启/停止等。
- 12 项核心回归检查：探测防抖、宽限与冷却、心跳间隔、计数清理、健康 JSON、HTTP 响应等。
- WPF 实际渲染截图检查，输出到 `artifacts/ui`；不是网页模拟截图。
- 本机已有缓存条件下的离线核心构建和客户端编译。

测试使用独立数据目录和本机回环 HTTP 服务，没有用真实校园网账号认证，也没有修改系统开机启动项。
仍需在真实学校网络验证断网重连、切换账户、睡眠恢复及连续约 48 小时的运行情况，不能把自动化检查等同于运营商环境验证。

## Pen 视觉对照

- 本轮通过 Pen 工具导出三页 HTML/CSS 到 `artifacts/pen-reference/index.html`，保留图层名和图层 ID，便于核对尺寸与样式。
- `app/ESurfingDialerLite/PenIcons.xaml` 使用该导出中的原始填充路径，保留 14 单位视口，不再手绘替代主页、日志、设置、账户和认证图标。
- 导航共用一个组件，图标统一 21 × 21，卡片及曲线区域按设计尺寸定位。
- 主页移除右上角重复的连接状态，只保留校园网按钮中的圆点指示；账户名、校园网状态、认证服务标题使用字体自然行高和上下留白，已检查 Noto 与微软雅黑的文字高度及卡片边界。
- 字体优先使用本机已有的 Noto Sans SC，缺少时回退到 Microsoft YaHei UI；不同字体环境仍可能存在字形差异。未把系统字体自动打包分发。
- WPF 不直接执行 CSS：布局和文字样式映射为 XAML，SVG 填充轮廓映射为 WPF Geometry。不会为显示界面额外引入浏览器内核。
