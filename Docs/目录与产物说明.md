# 目录与测试产物

更新：2026-10-30。项目采用单仓库多产品布局，参考AuriWeave的分类方式。

| 目录 | 用途 |
|---|---|
| `Products/Windows` | 当前C#/WPF客户端及其Kotlin认证核心，内部app/core/scripts/tests布局保持 |
| `Products/Docker` | 当前Kotlin/JVM Docker版，独立配置与认证实现 |
| `Products/DockerCpp` | C++ Docker实验版，保留实验开关和现场验收限制 |
| `Docs/Windows` | Windows使用、审查、稳定性与未来C++迁移资料 |
| `Docs/Docker` | Kotlin Docker说明；部署图文教程及配图位于`教程/` |
| `Docs/DockerCpp` | C++迁移规格与现场验收要求 |
| `Docs`根目录 | 跨产品索引、版本记录、协作规则及本机交接 |
| `Assets` / `Design` | 可公开的公共资源和项目设计原稿 |
| `Research` | 本机研究与外部参考资料，不提交GitHub |
| `Tools/maintenance` | 依赖本机清单的一次性迁移核对脚本，不提交GitHub |
| `artifacts/packages` | 本地测试与历史交付包，不加入源码Git提交 |
| `artifacts/legacy` | 原dist内容及仍有用的历史验证证据 |
| `artifacts/maintenance` | 本次迁移前摘要、移动映射、删除清单与核对结果 |
| `.worktrees` | Git登记的附属工作树，旧版对照用途，不是当前源码入口 |

未来Windows C++在获得实施授权后可新增`Products/WindowsCpp`；目前不创建空实现、不宣称完成迁移。主目录Products是已合并源码，旧工作树仍停留在自己的提交，不能拿旧路径继续构建当前产品。
