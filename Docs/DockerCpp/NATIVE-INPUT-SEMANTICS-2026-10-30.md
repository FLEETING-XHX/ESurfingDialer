# Android32/2082 原生接口输入语义分析

日期：2026-10-30。当前现场模块的输入预处理分析已完成本轮可验证部分；不是C++算法适配或现场认证通过。

## 范围与方法

沿用[已验证本机离线环境](LOCAL-OFFLINE-ORACLE.md)，固定原生库、模块、合成身份、Asia/Shanghai和gettimeofday时刻1793339591。所有实验在全新、非root、只读根目录、network:none容器中执行，不使用真实账号或调用服务端。

1. 冷启动分别执行27种合成输入的纯enc与enc后self-dec；两种调用序列的27组密文全部相同，排除本轮self-dec操作造成密文差异。
2. 在另一新容器中，将上述27组self-dec结果重新enc，27组均回到原密文。
3. 补充缺失、空值、重复local-time三项边界；补充完整合成ticket协议XML中probe字段1/7/8/9/15/16/17/31/32/33字节的十项有效长度用例。

这里的self-dec只用于建立当前原生接口的加密等价关系，不能直接认定其输出就是底层密码函数收到的全部原始字节，更不能当作服务端响应方向的黄金向量。后者仍需独立证据。

## 已观察到的行为

| 输入变化 | 观察结果 | 适配意义 |
| --- | --- | --- |
| 冷启动的a与33个a、只有空白 | 得到相同的80字符十六进制输出；self-dec是只有UTF-8 XML声明，重新加密该声明得到同一密文 | 原长度未被按原始字符串直接保留，不能用于判断分组、填充或支持算法 |
| 空字符串 | enc和self-dec均为空 | 与非空非法文本不同，不把空输入当合法协议 |
| 不完整XML | 本轮可被修复/丢弃部分内容；例如未闭合test节点的结果与空test节点等价 | 原接口对错误输入不严格；不据此要求C++复刻这种宽松行为 |
| 合法XML之后再传非法文本 | 与冷启动非法文本输出不同，本轮与空request的XML表示等价 | 存在调用上下文影响，非法输入不能作为独立稳定向量；尚未确定状态具体存储位置 |
| ticket协议中的local-time值改为另一个日期 | 密文不变；self-dec均显示固定模拟器时刻2026-10-30 13:53:11 | 输入时间被原生接口当前时间替换 |
| 删除local-time | 没有自动新增该字段 | 不把时间替换误写成总会插入字段 |
| 空local-time或重复两个local-time | 存在的节点均变为当前时间 | 本轮不是只替换第一个非空字段 |
| XML注释有无 | 密文相同，self-dec不含注释 | 注释在接口处理中被丢弃 |
| XML声明有无 | 合法ticket输入密文相同，self-dec含统一声明 | 声明会被规范化 |
| CDATA与同内容的实体转义文本 | 密文相同，self-dec显示实体转义形式 | XML按内容而非原始文本形式处理 |
| 自闭合空节点 | self-dec显示显式开始/结束标签 | 存在XML序列化行为 |
| 字段顺序、缩进、换行 | 可改变密文；CRLF在本轮self-dec显示为LF，空白文本节点部分保留 | 不能简单删除全部空白或任意排序字段 |
| ipv4值改变、未知字段A/B、增加字段 | 密文随内容变化，合成字段在self-dec中保留 | 不是只取固定字段，也未观察到将输入IP统一替换为合成IP |
| 中文、补充平面字符 | 本轮UTF-8合成内容保留 | 后续长度需按字节计算 |
| 完整XML中十个不同probe长度 | 十种长度均原样保留，十组完整密文互不相同 | 替代原先失效的裸文本长度向量 |
| 重复相同合法ticket输入 | 本轮固定时钟下密文相同 | 当前上下文可建立可重复向量，不推广到全部模块/随机状态 |

因此“前10个裸文本输出相同”不能说明密码算法忽略长度，也不能证明返回固定错误码。更准确的结论是：它们在该初始化状态下被原生接口处理为与仅XML声明相同的加密输入语义。

整体行为符合“XML读取/修改/再序列化后再加密”的解释；当前实验验证的是接口可观察结果与加密等价关系，尚未逐条追踪实际内部函数的数据流。

## 与当前C++实现的关系

C++当前Cipher直接处理传入字符串，Session自行生成协议XML。后续原生适配必须区分协议预处理与底层加解密，不将任意裸字符串向量作为完整协议兼容的证明。

额外用现有95个C++参考分支比较39组非空、self-dec所示XML表示与对应原生输出：最佳直接命中0/39，XML命中分支0。即便考虑本轮观察到的XML表示，也不能给D1C99DF9-02D1-412A-89B9-6EA6ADD79473随意增加旧算法别名。这一负结果仍不能单独证明所有基础密码组件不同，因为尚未还原原生内部全部封装。
