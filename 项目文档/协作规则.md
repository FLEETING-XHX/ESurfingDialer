# ESurfingDialer zcode / Codex 共用协作规则

本文适用于 zcode、Codex 和接手本项目的开发者。工具若不会自动读取本文件，请在任务提示中明确指定。开始开发先读本文件、[项目说明](PROJECT-GUIDE.md)、[开发交接记录](DEVELOPMENT-HANDOFF.md)及任务涉及的计划。

## 唯一项目目录

```text
C:\Users\FLEETING\Documents\Project\ESurfingDialer-Docker
```

本目录是 Windows 与 Docker 源码合并后的 Git 仓库。旁边的 `C:\Users\FLEETING\Documents\Project\ESurfingDialer-Windows-Client` 是另一份目录，不作为本轮同步目标。zcode 和 Codex 应打开同一个合并仓库。

## 接手、认领与交接

1. 阅读根目录 `AGENTS.md`、[项目说明](PROJECT-GUIDE.md)、本规则和[交接记录](DEVELOPMENT-HANDOFF.md)。按任务再阅读 [未来方向](ROADMAP.md)、[认证修复计划](AUTH-REPAIR-PLAN.md) 或问题记录。
2. 查看 Git 分支、`git status` 和现有 diff。保留所有未提交文件；不要把另一工具的改动误认为构建产物。
3. 在交接记录中登记任务、执行工具和准备修改的文件。执行期间另一工具不要编辑相同文件，也不要同时写入相同构建/测试目录。
4. 完成后写明修改文件、验证命令及目录、实际结果、未验证内容和遗留工作。下一工具接手时重新核对 Git 与文件状态。
5. 同一目录下改动可由两边直接看见；跨电脑时按用户授权使用 Git 提交和远端同步。不要复制整份目录作为常规同步方式。

如需真正并行开发同一模块，先建立各自的分支和目录，分别完成及验证，再审阅合并。没有用户授权时，不提交、推送、合并、打包或发布。

## 产品边界

- Windows 源码：`ESurfingDialer-Windows-Client/01_客户端源码/ESurfingDialer-Windows-Client`。
- Docker 源码：`ESurfingDialer-Docker/01_Docker源码/ESurfingDialer-Docker-Fixed`。
- Windows 和 Docker 的认证 UA、原生库、模拟架构与门户路径不同。不要未经证据验证直接复制覆盖。
- Windows 当前 2.3 是开发源码；v2.2 已发布但有认证失败反馈。Docker 当前 v1.3。源码版本变化不会自动更新历史安装包。
- 认证现场 Algo-ID、加密算法和真实端到端认证结果仍待验证。不要猜测密钥、混用算法参数，或把本地模拟测试写成真实认证已修复。
- 当前用户要求先继续源码变更，暂不打包。后续以用户最新明确指示为准。

## 隐私与验证

- 运行和回归命令见[项目说明](PROJECT-GUIDE.md)。只运行与本次修改相关且必要的验证，并记录真实输出。
- 区分本机 HTTP 模拟、原生操作替身和真实校园网端到端验证。
- 不将账号、密码、ticket、密钥、完整敏感 URL、原始 ZSM 或用户配置写入代码、Git 和交接记录。
- 改 UI 时按 WPF 实际渲染/交互验证；改认证恢复时覆盖失败、暂停、手动停止和成功清理边界。
- 完成后更新对应计划及交接记录，保留用户和另一工具的改动。
