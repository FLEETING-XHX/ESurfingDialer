# Windows 客户端使用说明

更新日期：2026-09-30。适用：现有 WPF 界面的 v2.3beta 与本地 v2.3beta.2 测试客户端。程序提供 Windows x64 离线安装包，包含 .NET、Java 21 和认证核心；实际认证需要连接学校网络。

目前的 v2.3beta 是已发布测试版，下载与旧包校验信息见[v2.3beta 测试说明](V2.3BETA-RELEASE.md)。本地 v2.3beta.2 已加入八项、六项及实际入口修复，位置与新包 SHA256 见[本地测试包记录](WINDOWS-LOCAL-BETA-2026-09-30.md)，未推送或发布。两者的现场认证兼容与长期稳定性均待验证。

## 安装与首次连接

1. 本地测试使用新目录中的 `ESurfingDialer-Windows-v2.3beta.2-Setup.exe` 并核对新包 SHA256；公开 [Releases 页面](https://github.com/FLEETING-XHX/ESurfingDialer/releases/tag/v2.3beta) 仍提供旧 `ESurfingDialer-Windows-v2.3beta-Setup.exe`，两者的说明与摘要不可混用。测试前退出旧程序并备份原账户配置。
2. 启动“ESurfingDialer Lite”，点击主页的账户管理入口；添加校园网账号、密码和可选备注，点击“保存账户”。
3. 选择要使用的账户，点击主页“校园网”卡片开始连接。显示“已连接”表示客户端依据认证与心跳状态确认连接；还应打开网页核对学校是否已放行。
4. 测试期间保留原有可用认证方式。切换认证程序时先停止上一程序，避免两个程序同时操作同一账户。

## 账户、停止与后台运行

- 添加、编辑和删除在账户管理面板完成；重复账号会提示编辑已有账户。顶部优先显示账户备注，没有备注时显示账号。
- 切换正在使用的账户会先停止旧核心，再使用新账户连接；删除当前账户会停止连接。修改失败时查看提示，不把“保存失败”当成认证成功。
- 连接中或已连接时，再次点击“校园网”卡片可停止认证。
- 关闭窗口会隐藏到托盘；需要显示时使用托盘菜单。完全退出可在设置页或托盘菜单选择“退出”。退出会停止认证核心。
- 已发布旧包仍应手动避免重复启动；本地 v2.3beta.2 已包含按配置目录识别的单实例保护。仍需现场验收真实安装后的重复启动/退出行为。

## 设置含义

| 设置 | 行为 |
| --- | --- |
| 开机自启 | 登录当前 Windows 用户后启动客户端；设置会自动保存 |
| 启动后最小化到任务栏后台 | 开启自启后可配置；开机启动时隐藏窗口保留托盘，手动启动通常仍显示窗口 |
| 自动连接 | 程序启动后连接当前选中的账户，需要账户密码可由当前用户解密 |
| 增强连接 | 根据健康状态判断异常并进行有次数、冷却和退避限制的恢复；关闭后核心普通心跳/掉认证恢复继续工作 |
| 详细日志 | 打开近期客户端和核心日志；不是无限读取全部历史日志 |
| 导出日志 | 选择保存位置，生成脱敏 ZIP；不导出账户配置、加密密码或账户列表 |
| GitHub | 打开本项目仓库 |

主页上下行速率是活动网卡流量，不是校园网账号剩余流量，也不是某个应用的独立流量。托盘颜色随连接状态变化；当前界面仍主要使用“连接中/已连接/连接失败/已断开”，更细的恢复/暂停提示属于[待优化项](PENDING-OPTIMIZATIONS.md)。

## 出现问题时

| 现象 | 先检查什么 |
| --- | --- |
| 一直连接中或显示连接失败 | 打开详细日志，记录发生时间和失败阶段；确认运行包版本。会话初始化失败不能直接判定为密码错误 |
| 提示填写账号密码，但配置原来能用 | 检查是否更换 Windows 用户、迁移了配置或密码保存损坏；密码用当前用户 DPAPI 保护，必要时重新编辑账户输入密码 |
| 自动恢复已暂停 | 根据日志区分相同确定性认证错误或达到恢复上限；处理原因后手动停止再连接，反复重启不能修复不兼容算法 |
| 配置读取/保存失败 | 原配置读取失败时程序会保留文件并阻止覆盖；先备份本机配置，再核对文件/目录权限。不要公开分享配置内容 |
| 从休眠恢复后异常 | 记录休眠/唤醒时间、网络变化和界面状态，导出日志；实际系统休眠仍属于待现场验收场景 |

日志目录为 `%LOCALAPPDATA%\ESurfingDialerLite\logs`。在设置中选择“导出日志”和保存位置。反馈时提供：客户端/安装包版本、发生时间、Windows 环境、连接方式、操作步骤、错误提示和经过检查的脱敏日志。

不要公开账户配置、密码、票据（ticket）、密钥、原始 ZSM 或带敏感查询参数的完整 URL。跨用户复制配置可能无法解密密码，重新录入通常比修改加密字段可靠。

## 升级与验证范围

升级测试前退出旧客户端，保留本机配置备份和原可用认证方式。使用新版说明中的安装步骤与校验信息；安装升级、卸载、自启清理和回滚流程尚未完成实机验收，本说明不将它们写成已验证结果。

连续使用的验收建议为先 72 小时，再 7–14 天，并覆盖一次实际认证周期、断网、切网、休眠、切账户和手动停止。记录问题原因与后续验证，详见[稳定性与迁移基线](WINDOWS-STABILITY-AND-MIGRATION-BASELINE.md)。
