## 已确认的失败位置

用户提供的日志覆盖 14:49:06–14:50:01。应用加载设备身份并启动，随后在 14:49:07、14:49:12、14:49:22、14:49:42 四次认证前置发现过程中失败；最后记录 shutdown，其触发原因未出现在日志中。

堆栈对应修复前的 [PortalConfiguration.kt](../ESurfingDialer-Docker/01_Docker源码/ESurfingDialer-Docker-Fixed/src/main/kotlin/com/rsplwe/esurfing/PortalConfiguration.kt)，以下行号为当时基线：

1. `discover:81`：GET 门户响应，检查 HTTP 成功状态和 128 KiB 长度上限后，调用页面解析。可以确定这次响应通过了这些检查，不代表门户业务配置有效。
2. `parse:48`：执行 `tag("auth-url")`。
3. `parse$tag:44`：正则匹配数量 `values.size != 1`，抛出 `PORTAL_CONFIG_INVALID`。

因此，当时的直接原因是：已识别的门户配置块中，旧解析器没有匹配到唯一的 `auth-url` 字段。匹配数量可能是 0 或大于 1；这份 beta2 日志无法区分。

执行已经通过配置块起止标记检查，错误尚未到 `ticket-url`、端点路径或 IP 校验。认证在 [Client.kt:171](../ESurfingDialer-Docker/01_Docker源码/ESurfingDialer-Docker-Fixed/src/main/kotlin/com/rsplwe/esurfing/Client.kt#L171) 发现门户时中断，未执行后面的 `LOGIN_ATTEMPT`、原生会话初始化、ticket 请求、账号密码登录或心跳确认。这份旧日志不能判断账号密码、原生算法是否可用。

## beta2 日志当时无法区分的原因

| 可能情况 | 修复前表现 | 当时缺少的证据 |
| --- | --- | --- |
| 配置确实缺少 auth-url，或内容不完整 | 匹配 0 次 | 配置块中字段存在性、闭合状态及页面类型 |
| 字段存在，标签或内容格式与正则不一致 | 匹配 0 次 | 脱敏后的标签结构，例如标签空格/属性、命名、CDATA 与文本混合形式 |
| 同一配置块中重复 auth-url | 匹配大于 1 次 | 字段数量及是否是重复模板或多个不同端点 |
| 门户请求拿到模板、提示页或错误的落地页面 | 配置标记存在，但字段结构不满足要求 | GET 跳转链、最终响应状态/类型、落地路径和配置结构 |

beta2 原正则要求精确的 `<auth-url>` 和 `</auth-url>`，内容只能是一个 CDATA 段或不含 `<` 的普通文本；没有通用 XML 结构解析。它可能拒绝 XML 中合法但未支持的写法。具体现场是否属于这种情况，必须用样本确认。

本地 C 参考附件同样提取这两个配置标记和字段，但其 `xml_parser` 只取第一组精确标签，没有重复字段检查。它不能证明现场字段一定存在，也不能证明直接复制 C 解析器可以解决问题。

## 重复错误的原因

`Client.run:137–143` 将此异常作为一般异常处理，清理状态后继续退避重试。日志中的约 5、10、20 秒间隔与该退避逻辑一致，期间没有再次出现应用启动日志，说明这些是客户端循环重试，不是日志所示的容器反复启动。

在 beta2 基线中，`AuthenticationFailure` 虽带 `deterministic` 标志，Docker 运行代码没有消费它；没有原生会话时 `resetSessionState` 也不会增加 recoveries。相同解析失败因此可能持续重试并输出堆栈。最后的 shutdown 无法据此认定为超时退出或崩溃。

10-08 新诊断进一步定位到属性查询串裸 `&` 和两个规范化相同的 auth 地址；这不是从旧 beta2 日志反推的完整页面。后续保留的诊断仅含结构、计数和固定类别，不含字段值或门户身份，具体复现依据见[现场记录](DOCKER-BETA3-PORTAL-FAILURE-2026-10-07.md)。

## 09-28 已实施的修复

- `PortalConfiguration.kt`：使用有界 XML 结构解析配置片段/带声明的配置文档，支持标签空白、属性、配置包装、多个 CDATA 片段、CDATA 与文本混合、标准和数字实体。保留普通 URL 中常见的原始 `&key=value` 分隔符兼容，CDATA 不做二次转义。DTD/外部实体/外部资源禁用，XML 深度限制 64，页面长度限制继续保留。
- 当轮要求 auth/ticket 各唯一，并保留非空值、禁止字段内嵌元素、HTTP(S)/端点/IP 校验。缺失、重复、空值、结构错误、URL 错误分别返回具体代码；重复配置块和坏配置不会静默使用旧入口。10-08 仅将 auth 放宽为逐项校验后按规范化地址去重；任一坏成员或不同地址仍拒绝，ticket 仍唯一。
- 缓存页面失效且有门户 URL 时，重新进行有限 GET 发现；新页面提供有效配置后恢复。新页面也无配置时保留原失败，并用 `cachedConfig=true` 标明字段统计来自缓存，不混淆成新页面内容。
- 新增 `PortalDiagnostics.kt`：只记录长度、配置块和字段数量、HTTP 状态、跳转步数与固定媒体类别，不记录完整 URL、IP、字段值、原始响应或 XML 解析异常文本。`-1` 表示未采集/未知，不能视为零个字段；`hop=0` 表示本地页面解析。
- `Client.kt`：预期认证错误输出单行诊断，同一候选入口/IP 和错误码每 60 秒最多记录一次并汇总抑制次数；页面正文或长度变化不绕过日志限频。继续有界退避和定期发现，候选发生变化可在最多一个 5 秒等待片段后重新尝试；成功后重置失败记录。
- 停止期间的异常处理等待也纳入退出清理；最终健康状态写入前临时清除中断标志，写完恢复，避免 NIO 因中断而留下旧的线程存活状态。
