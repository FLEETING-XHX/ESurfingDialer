# Docker C++：原生差分与现场验收门槛

日期：2026-10-30。此文件是后续验证规格，不是已执行的生产操作。当前保持Kotlin回退；不读取真实.env、不使用用户凭据、不替换生产容器，不创建定时任务。

## 当前证据与缺项

旧Docker源码的Constants.kt使用CCTP/Android8_vpn/2082，hook/AndroidMock.kt明确for32Bit()，资源libdaproxy.so的SHA256为69948f5005c308166f7de48a0520edde792ad786ed3bf52d6d0d674d6b055a3c。本轮只读源码和计算摘要，没有执行该原生库。

Session.kt的正式接口顺序是load(模块字节)→aid(handle)，其后enc/dec使用该句柄，结束free(handle)。模块头部候选UUID不能直接代替aid返回值。当前Research保存的官方Windows .zxm与Windows 2104历史日志，均不能补上此Docker通道的实际模块和可重建上下文；本轮文件清单未找到可用的2082原始.zsm与方向性黄金向量。只有动态模块响应摘要、候选ID或成功日志，无法还原这些字节。

C++的95分支参考输出、参考自身往返、合成HTTP闭环、ARMv7/ARM64 Docker仿真都已有独立用途；它们不等同于上述原生库在同一实际模块下的输出。Linux ARM镜像能执行，也不代表Android认证算法已经等价。

## DCPP-VALIDATE-01：先取得可离线复现的原生证据

需要由后续获准的受控取证取得以下资料，当前不联网补取、不运行官方模块来凑结果：

| 材料 | 必须记录 | 缺失时的处理 |
| --- | --- | --- |
| 正确通道模块 | Android32/2082、响应原始字节、长度、SHA256、来源时间 | 标记MODULE_MISSING，不能拿2104或虚构UUID替代 |
| 实际原生身份 | 指定lib摘要、load成功、aid实际返回值、头候选值及二者关系 | 标记AID_UNVERIFIED，不能默认等于候选 |
| 可重建会话 | 明确MAC/Client-ID、合成IP/输入、随机/时间/序列条件、调用顺序与释放边界 | 标记CONTEXT_INCOMPLETE，不要求无条件密文相等 |
| 同方向输出 | 请求enc输入/输出完整字节；独立合法响应密文的dec输入/输出完整字节 | 标记DIRECTIONAL_VECTORS_MISSING，不用enc→dec自身往返替代 |

尽量只使用合成XML和合成身份，不包含真实账号、密码、ticket或用户网络标识；不能把线上原始请求/响应直接放入公开fixture、日志或发布包。保留模块与oracle产物的来源、摘要和实验命令；默认不输出密钥。已有参考数据的来源等级保持不变。

最小输入集覆盖UTF-8字节长度0、1、7/8/9、15/16/17、31/32/33，中文/补充平面字符，以及XML转义和CR/LF。零字节只在原生接口契约确认允许后测试。比较请求方向、响应方向、hex大小写/长度、首尾字节和错误分类；重复同会话与新会话调用，检查状态依赖。

若不相等，先定位选择算法、编码、显式长度、填充/封装、方向和上下文；不裁掉不理解的前后缀来制造一致。历史Windows原生实验曾出现字符串往返长度不同，因此不能强加dec(enc(x))==x作为官方接口已知契约。只对有独立证据的分支登记等价；不能用一例覆盖95分支。

## DCPP-5：获得明确现场操作授权后执行

在原生差分达标前，不把实验Compose改成生产默认。现场测试须避开现有连接的使用时段，并先确认旧核心的停止/回退安排；新状态目录只能复制稳定快照中的身份和计划，不能与Kotlin共享活动卷或同时用同一账号认证。

| 场景 | 验收关注点 | 目前证据边界 |
| --- | --- | --- |
| 首次认证，服务端延迟5–10秒 | authorizing/confirming均authenticated=false；首次keep成功才online | 已有合成链路；现场待验 |
| 浏览器能上网，但无本进程会话 | external_online、networkOnline=true、authenticated=false；无无限补登/重启 | 已有离线状态与真实进程替身；旧服务端会话仍有效也可能造成该现象 |
| 登录返回后首次keep失败 | 不假报已认证；有限确认和恢复预算 | 已有合成回归；现场待验 |
| 探测慢/失效，但本会话keep正常 | 探测线程不饿死keep，报告继续更新 | 已有线程和实际进程回环；现场链路待验 |
| 同门户/换门户/换IP | 同候选计数、宽限/冷却不被成功keep延长；旧响应不能推进新代次 | 已有离线策略和请求测试；现场切网待验 |
| 心跳短暂失败后恢复 | 恢复事件只记录一次，恢复预算只按正式确认规则处理 | 已有合成测试；不能用外网恢复冒充本会话恢复 |
| 未知/轮换模块 | 有界取模块，未知ID明确paused；外网观测仍更新 | 已有实际进程合成用例；运营商真实轮换待验 |
| 主动停止/进程异常退出 | PID1停止、无残留写入者/旧健康覆盖；TERM_REQUEST_SENT_UNCONFIRMED不当作注销确认 | 已有实际容器/子进程；服务器注销语义待验 |
| 定期重认证 | UTC+8窗口、计划持久化和回拨；只在新首次keep后记成功 | 已有合成时钟；至少覆盖一个真实周期后才能验收学习 |
| 文件满/日志失败/健康停更 | 有界队列、不阻塞心跳；失败退出；watchdog冷却且不误杀新实例 | 已有合成/实际管道和容器守卫；不可中断内核I/O仍靠容器停止兜底 |
| 手动停止/暂停容器 | watchdog永不主动启动；默认关闭，restart:no实验服务不回收 | 已有替身和实际守卫；实体OpenWrt安装待验 |
| 物理ARMv7/ARM64路由器 | 内核、Docker、glibc/time64、只读根目录、UID/卷权限、信号、资源 | 当前ARM仅Docker CPU仿真 |

资源验收应记录首次认证、解密、正常心跳、重试/切网、重认证的峰值与稳定期CPU/内存，并观察至少一个计划周期。当前隔离无会话容器的docker stats只是空闲快照，不能拿来承诺认证峰值或长期稳定性。镜像逻辑大小、ELF大小、压缩下载大小、进程RSS与容器内存也必须分开。

## 回退与停止条件

如原生差分不匹配、身份变化、认证误报、恢复无界、状态覆盖或持续增长，停止实验并保留固定错误码、版本/镜像摘要和经过脱敏的时间线。保留旧身份/计划与原Kotlin部署配置；不删除旧卷、不执行down -v、不把新schema3健康文件复制回旧目录。文件级回退演练已通过，实际生产容器回退尚未执行。

现场没有提供以上资源时，迁移可以继续做独立源码/打包/离线兼容工作，但最终状态必须保留“原生等价和现场未通过”，不能以额度用完或编译通过替代验收。
