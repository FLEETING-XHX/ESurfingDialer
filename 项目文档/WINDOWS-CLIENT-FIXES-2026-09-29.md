## 设计边界

- Windows 的 Android64 原生库、UA、设备身份及算法选择保持原样。门户通用解析逻辑参考本仓库 Docker 实现，并单独在 Windows 编译和回归；Windows 自身的 Constants、HTTP 通道与原生提供者仍独立。
- 三次同类确定性认证错误后的暂停继续有效；普通唤醒不会解除暂停，入口变化或用户手动重连可恢复尝试。重试等待使用单调时钟，普通唤醒不会直接跳过退避。
- 心跳等待宽限与具体操作的宽限分开。协商间隔按现有运行配置上限约束；心跳/认证等操作最多 90 秒进展期限。增强模式可执行进程恢复，关闭增强模式不会开启新的自动重启。
- UI 的健康恢复轮次上限仍为三次；每一轮停止/启动失败最多尝试三次。崩溃恢复保留原有连续退出和五次启动尝试上限。取消令牌与进程代次共同防止旧账号延迟任务恢复。
- 单实例锁由进程持有，退出由操作系统释放，不依赖 PID 文件是否陈旧；激活事件不传递账号、密码或任意命令。健康 JSON 中新增的实例 ID 只用于本机区分运行实例。
- 新增的 `AuthenticationSession` 接口用于替换测试中的原生操作；生产默认仍实例化 Windows `hook.Session`，没有新增算法或更换 JNI 库。
